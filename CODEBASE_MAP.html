The one-paragraph mental model

The system never decodes brain → words directly. Instead it learns a forward (encoding) model that predicts brain response from words, then inverts it at test time by guessing word sequences and keeping whichever ones would have best produced the brain activity actually recorded. A language model (the original OpenAI GPT) proposes plausible next words; the encoding model scores them against the real fMRI; a beam search keeps the best running sentences.

How the two halves relate

Forward model (training)

Words → GPT semantic features → linear ridge weights → predicted fMRI. Fit once per subject. Produces encoding_model_*.npz (weights + a noise covariance model).

Direction: stimulus ⟶ brain

Inverse search (testing)

For each moment, GPT proposes candidate words; each candidate is pushed through the frozen forward model and scored by how well its predicted fMRI matches the recording. Beam search keeps the best sentences.

Direction: brain ⟵ guess-and-check words

Mental shortcut for training

The whole of training is "build a feature matrix from words, build a response matrix from fMRI, ridge-regress one onto the other." The encoding model regresses 3,072 GPT features → 81k voxels; the word-rate model regresses delayed ROI responses → a single words-per-TR number. Same engine (bootstrap_ridge), different inputs.

Why testing feels different from training

Training is a couple of big batch matrix operations. Testing is a sequential loop: every word time depends on the surviving sentences from the previous one, and each step calls GPT several times. You can't collapse it into one matmul — which is exactly why decoding is the GPU-bound, wall-clock-dominant stage.

Practical gotchas before you run

① RAM is the real limit for train_EM.py — the 8.9 GB response matrix plus SVD intermediates wants ~16–32 GB free.

② ridge.py has a stale from text.regression… fallback import that only triggers if NumPy's SVD fails — harmless unless you hit it.

③ Decoding time scales with story length × beam width (200) × nucleus size; shrink WIDTH in config.py:29 to iterate faster while learning.

Knobs that change cost (all in config.py)

NBOOTS=50 · bootstrap count → linear on encoding-fit time.

VOXELS=10000 · kept voxels → noise-model size (²) & decode scoring.

WIDTH=200 · beam width → decode time & quality.

GPT_LAYER=9, STIM_DELAYS · set the 3,072 feature dim.

Smallest possible first run (to verify the plumbing)

Train on a handful of sessions with --sessions 2 3, drop NBOOTS to ~5 and VOXELS to ~1000, then decode one short task with WIDTH≈20. The numbers will be poor but every file in the pipeline will execute, which is what you want while learning the codebase.
